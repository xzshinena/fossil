## Problem Statement

No existing tool combines multi-source composite language health scoring with an interactive phylogenetic tree visualization and time-scrubbing. TIOBE, PYPL, SO surveys, and GitHub Innovation Graph are all single-source, league-table style. GitHut 2.0 and OSSInsight are GitHub-only. The evolutionary metaphor — languages branching, forking, dying, influencing each other — doesn't exist as an interactive web tool anywhere.

Fossil fills that gap: a composite Health Score (0–100) per language per month, rendered as a living phylogenetic tree where you can scrub through history and watch the entire evolution of programming play out.

## What Makes This Cool

- **The hero moment**: an animated phylogenetic tree where languages branch, grow, shrink, and die — driven by real composite data, scrubbing through 15 years of history with a timeline slider.
- **Historical event annotations**: TypeScript 1.0, Python 3 adoption inflection, Rust 1.0, LLM-era Python explosion pinned to the timeline — framing Fossil as a *narrative*, not a dashboard.
- **Multi-source composite scoring**: GitHub activity + SO survey sentiment + job market demand + academic citation counts → single Health Score. No existing tool does this.
- **The "evolutionary replay" framing** (Codex's insight): not ranking languages, showing that they evolve through shocks, inheritance, and niche adaptation.

## Constraints

- Timeline: a few weeks (hard; portfolio must be presentable to employers)
- Tech stack: non-negotiable (Django, Pandas, Scala/Akka/ZIO, MySQL, MongoDB, Angular/D3, GCP, Power BI) — every layer must be present and clean
- Deliverable: GitHub repo + Docker Compose + demo video (no live deployment needed)
- Maximize use of premade data, open source libraries, and existing tools to reduce build time

## Approaches Considered

### Approach A: Hero First, Backfill (Selected)
Build the animated phylogenetic tree with static/curated data in week 1. Layer in real pipelines afterward. Add event annotations in the final week. Always have a demo-able artifact.
- Effort: M (2-3 weeks core + 1 week polish)
- Risk: Low

### Approach B: Full Stack Sequential
Data pipelines first, frontend last. The "wow moment" comes late — risk of running out of steam.
- Effort: L (4-5 weeks)
- Risk: Med

### Approach C: Narrative / Evolutionary Replay System
Design Fossil as a paleontology sim from day one. Ambitious and content-heavy; event curation is a labor-intensive content problem, not an engineering problem.
- Effort: L-XL (4-6 weeks)
- Risk: High

## Recommended Approach

**Approach A + C hybrid, executed in four weekly layers.** The C component is scoped to exactly 10–15 hand-curated annotations (listed in Week 4); no generative or automated event curation — this bounds the content-labor risk.

### Week 1 — Hero Moment (Tree + Static Data)
Goal: a beautiful, demo-able phylogenetic tree by end of week.

**Premade resources to use immediately:**
- **phylotree.js** — D3-based phylogenetic tree library, built for exactly this rendering pattern. GitHub: `veg/phylotree.js`. Wire it into the Angular component as an encapsulated D3 service (per idea.md's architectural note).
- **Language lineage JSON** — curate from Wikipedia "History of programming languages" (well-documented). ~20 languages to start: C, C++, Java, Python, Ruby, Perl, JavaScript, TypeScript, Go, Rust, Kotlin, Swift, Scala, Haskell, Lisp, Fortran, COBOL, PHP, R, Julia.
- **Stack Overflow Developer Survey CSVs** — publicly available back to 2011 at `survey.stackoverflow.co/datasets`. Use these as the initial static data source; no scraping needed.

**What to build:**
- **Day 1: `data/lineage.json`** — hand-curated language parent-child relationships from Wikipedia (20 languages). This is the backbone of the tree; everything else renders from it. Format: `[{"name": "C", "parent": null}, {"name": "C++", "parent": "C"}, ...]`. Required before the Angular tree component can render anything.
- Django project skeleton with **split settings**: `backend/settings/base.py` (shared config), `settings/dev.py` (DEBUG=True, local DB), `settings/prod.py` (Cloud Run env vars). Never a single `settings.py`.
- **`backend/asgi.py`** with `ProtocolTypeRouter`: routes HTTP requests → Django DRF, WebSocket connections → Django Channels consumers. Required from Day 1 so the Docker Compose ASGI server (Daphne/Uvicorn) starts correctly.
- Django REST API endpoints: `/languages/`, `/health-scores/`, `/tree/`
- MySQL schema: `languages` (id, name, parent_id), `health_scores` (language_id, year, month, score, partial, source_breakdown JSON). Add composite index on `(language_id, year, month)` for `/tree/` query performance.
- Pandas seed script that reads SO survey CSVs → computes simple health scores → seeds MySQL
- Angular tree component using D3 tree layout (`d3.hierarchy` + `d3.tree`) → reads `/tree/` endpoint → renders animated SVG. **`/tree/` response format**: returns a nested JSON with `name`, `children[]`, and `health_score` fields per node — standard D3 hierarchy format. (phylotree.js parses Newick strings and does not consume this JSON directly; use it only if Newick export is preferred, otherwise use D3 hierarchy natively.)
- Time slider (D3 brush) that scrubs through months → re-renders tree with score-proportional node sizes and color. **Slider granularity**: monthly steps (180 ticks for 15 years). **Node radius scaling**: `radius = 4 + (health_score / 100) * 20px`, linear. **Smooth animation**: use `d3.selectAll(".node").transition().duration(150)` on each slider tick — avoids jank during rapid drag.
- Docker Compose: Django + MySQL + Angular + Redis (required for Django Channels multi-worker support; add from Day 1, not Week 3)

### Week 2 — Real Data Pipeline
Goal: replace static seeds with real ingestion.

**Data source coverage (actual ranges):**

| Source | Coverage | Notes |
|--------|----------|-------|
| GH Archive (BigQuery) | 2011–present | Full monthly coverage; free public dataset |
| SO Developer Survey | 2011–present | Annual snapshots only — interpolate for monthly scores |
| TIOBE | ~3 years free | Paid subscription for older data; use where available, `partial=True` otherwise |
| Semantic Scholar | Historical via API | Rate-limited (100 req/5 min); covers academic citations back to ~2000 |
| Adzuna Jobs API | Current + ~2 years | Free tier 250 req/month; historical backfill at annual granularity only (see TODOS.md) |

**Premade resources:**
- **GH Archive via BigQuery public dataset** (`githubarchive.*`) — query GitHub event history (PushEvent, CreateEvent) via SQL against BigQuery's free public dataset. Zero file download. Filter by language in the query WHERE clause. Do NOT use the hourly file download approach (131K+ gzip files = terabytes of transfer; BigQuery public dataset is free and instant).
- **SO survey CSVs** — already covered in Week 1. **Sub-score definition**: use "Admired %" column (% who have worked with the language AND would use it again, i.e. love-not-dread). Pre-2015 CSVs use different column names — see `TODOS.md` (TODO-1) for the mapping table.
- **TIOBE rankings RSS/scrape** — use BeautifulSoup. Only ~3 years of free historical data; flag older months as `partial=True` for TIOBE sub-score.
- **Semantic Scholar API** — free academic paper search, no scraping needed.
- **Adzuna Jobs API** — free tier, JSON REST, no legal issues. For the historical backfill, query at annual granularity only (300 requests total, within free tier); interpolate monthly values. See `TODOS.md` (TODO-3) for rate-limit handling strategy.
- **GrimoireLab** is referenced for ingestion architecture inspiration only — not used directly. The actual pipeline is the five custom `ingest_*.py` scripts.

**What to build:**
- Pandas ETL pipeline — five scripts, each independently runnable and idempotent:
  - `ingest_github.py` — queries BigQuery `githubarchive.*` public dataset (SQL: PushEvent + CreateEvent counts per language per month). **Add**: `timeout=120` param on the BigQuery query; catch `google.api_core.exceptions.DeadlineExceeded`, log the error, mark that month as `partial=True` rather than failing the entire run.
  - `ingest_so.py` — reads SO survey CSVs, extracts Admired % per language per year. Use `{year: column_name}` mapping dict for pre-2015 column name differences (see TODOS.md TODO-1).
  - `ingest_tiobe.py` — BeautifulSoup scrape of TIOBE; use available data, skip unavailable years gracefully.
  - `ingest_scholar.py` — Semantic Scholar API; respect 100 req/5 min rate limit.
  - `ingest_adzuna.py` — Adzuna Jobs API; annual-granularity historical backfill, monthly for forward ingestion. Rate-limit handling per TODOS.md TODO-3.
  - After each script writes to MongoDB: **publish a message to Pub/Sub `raw-events` topic** (`{source, language_id, month, year, raw_value}`). This triggers the Scala streaming service in Week 3.
- Composite health score algorithm: `compute_health_score(github, so, tiobe, scholar, adzuna)` — weighted average (GitHub 30%, SO 25%, job demand 25%, academic citations 20%). **Missing-source handling**: if a source is `None` for a given month, redistribute its weight proportionally across the remaining sources and flag that row as `partial=True`. **Edge case**: if ALL sources are `None`, return `None` (do not divide by zero). **Ingestion failure policy**: on HTTP failure or scrape error, log the error, skip that month's data for that source, allow the score to be computed with `partial=True`.
- MongoDB raw store: each ingested document stored before normalization
- Normalized scores persisted to MySQL

### Week 3 — Scala Streaming Layer
Goal: wire the Scala service into the pipeline for real-time score updates.

**Premade resources:**
- **Akka Streams quickstart** — official docs have complete streaming pipeline templates
- **GCP Pub/Sub emulator** — local emulator for Pub/Sub, enables full testing without GCP billing
- **ZIO ↔ Akka Streams interop**: use `dev.zio:zio-interop-reactivestreams` (not `zio-akka-cluster` — that's a clustering library). Bridge via `ZStream.fromPublisher` / `Sink.asPublisher` from `zio.interop.reactivestreams._`.

**What to build:**
- **`streaming/build.sbt`** — add `dev.zio:zio-interop-reactivestreams` as a dependency. Use a **multi-stage Dockerfile** for the Scala service: first stage copies `build.sbt` and runs `sbt update` to cache dependencies in a Docker layer; second stage copies source and runs `sbt assembly`. Without this, every Docker build downloads all dependencies (~15–20 min cold start).
- Scala service: subscribes to Pub/Sub `raw-events` topic → parses events → updates a 30-day rolling count for the affected language → recomputes only the GitHub activity sub-score (or SO sub-score) → emits a delta message `{language_id, sub_score_type, delta, timestamp}` to `score-updates` topic. Full composite score recomputation remains in the Pandas batch pipeline.
- Django API WebSocket endpoint: subscribes to `score-updates` and pushes to Angular via Django Channels. **Implementation**: use a Django Channels `AsyncConsumer` that, on WebSocket connect, starts a background `asyncio` task using `AsyncSubscriberClient` from `google.cloud.pubsub_v1.services.subscriber.async_client` (NOT the standard synchronous `SubscriberClient` — synchronous `pull()` blocks the ASGI event loop). Loop calls `await subscriber.pull(...)` and `await self.send()` for each message. Requires `google-cloud-pubsub` in the Django container and `CHANNEL_LAYERS` backed by Redis. **WebSocket auth**: connections are unauthenticated; set `CHANNEL_LAYERS` max connections to 10. **Latency caveat**: Pub/Sub emulator adds ~50–200ms per message on localhost; tree animation updates at a minimum ~200ms interval, acceptable for portfolio demo.
- **Angular WebSocket auto-reconnect**: on `WebSocket.onclose`, implement exponential backoff reconnect at 1s, 2s, 4s, 8s intervals (cap at 30s). Show a subtle "Reconnecting..." indicator in the UI during disconnect. This is in the Key Interactions to Verify test list — it must be built, not just tested.
- Docker Compose update: add Scala service container + Pub/Sub emulator (Redis already added in Week 1)
- Angular live-update component: animates tree node resizing as score updates arrive. Use `d3.selectAll(".node[data-id='" + update.language_id + "']").transition().duration(150)` to animate to the new radius.
